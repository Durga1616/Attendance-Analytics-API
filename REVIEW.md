# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns hard-coded `{"status": "ok"}` without verifying database connectivity. Fails to return HTTP 503 when MongoDB is down. | Stopping MongoDB and requesting `GET /health` returned HTTP 200 instead of HTTP 503. | Added `client.admin.command("ping")` within a try/except block that raises HTTP 503 when ping fails. |
| 2 | `compute_late_minutes` (lines 33-37) | Ignores timezones (mixes UTC and naive time), does not truncate fractional seconds before calculation, and ignores overnight shift context. | Punch-in at 09:40:00.900 IST treated as late; UTC punch time directly compared with IST hour/minute without timezone conversion. | Converted `punch_in` to IST, truncated to whole seconds, constructed attendance date's shift start in IST, and computed `diff_sec > 600` for whole floor minutes elapsed since `shift_start`. |
| 3 | `compute_work_hours` (lines 40-41) | Uses Python built-in `round()`, which applies Banker's Rounding (round half to even) rather than Decimal `ROUND_HALF_UP` mandated by R4. | An elapsed duration of 32850 seconds (9.125 hours) rounded to `9.12` instead of `9.13`. | Replaced with `decimal.Decimal` and `ROUND_HALF_UP` quantized to `Decimal("0.01")`. |
| 4 | `compute_overtime` (lines 44-47) | Counts any positive minutes past shift end (`max(0, ...)`), ignoring the mandatory 30-minute threshold in R3. Fails on overnight shifts where `shift_end` is on the next day. | Punch-out 10 minutes after shift end returned 10 overtime minutes instead of 0. Overnight shift (22:00-06:00) compared against same-day 06:00 IST. | Evaluated overnight shift to roll `shift_end_date` to next day, required `diff_sec >= 1800` (30 min) to count overtime, and floored to whole minutes. |
| 5 | `create_employee` (lines 77-85) | Vulnerable to race conditions via check-then-insert (`find_one` then `insert_one`). Lacks schema validation (emp_code format, shift inequality) and returns naive datetime for `created_at` rather than epoch ms. | Concurrent requests with identical `emp_code` created duplicates. Passing identical `shift_start` and `shift_end` succeeded. `created_at` was not an integer. | Created unique index on `emp_code`, caught `DuplicateKeyError` to return HTTP 409, enforced Pydantic v2 validators, and serialized `created_at` to integer epoch ms. |
| 6 | `list_employees` (lines 88-96) | Off-by-one pagination bug (`skip = page * page_size`), completely skipping page 1. Missing `emp_code` ascending sorting. `total` ignored `department` filter. | Requesting `page=1&page_size=20` skipped the first 20 records. Total count for filtered department returned total count of the entire collection. | Corrected skip formula to `(page - 1) * page_size`, added `.sort("emp_code", ASCENDING)`, filtered `count_documents(q)`, and formatted `created_at`. |
| 7 | `punch_in` (lines 99-121) | Raises unhandled `TypeError` (HTTP 500) if employee does not exist. Does not map overnight shifts to previous day's attendance date. Check-then-insert race condition. Injects forbidden `id` in response. | Punching in for unknown employee returned 500. Punching in at 05:30 IST on an overnight shift assigned current day instead of previous day. | Added 404 check, implemented R1 overnight shift date mapping, created unique compound index on `("emp_code", "date")`, caught `DuplicateKeyError` (409), and conformed response to contract. |
| 8 | `list_attendance` (lines 124-150) | Loads full collection into Python memory (`list(db.attendance_logs.find(q))`), sorting and slicing in Python. Does not validate `date_from <= date_to`. Missing secondary sort on `emp_code`. | Severe performance degradation and high memory usage on ~100k records. Request with `date_from > date_to` returned 200 instead of 422. | Replaced with database-level sorting (`[("date", -1), ("emp_code", 1)]`), pagination (`skip`, `limit`), and `count_documents(q)`, and added 422 validation for date ranges. |
| 9 | Missing Endpoints (lines 154-162) | Endpoints marked TODO (`POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, analytics, and explain) were unimplemented. | Calling any unimplemented endpoint returned HTTP 404 or 405. | Implemented all endpoints matching `openapi.yaml` specifications, concurrency protection, and MongoDB aggregation pipelines. |
| 10 | Database Startup / Indexing | Starter initialized no indexes at startup, leading to full collection scans (`COLLSCAN`) and failure of uniqueness guarantees. | MongoDB explain commands revealed `COLLSCAN`; race condition tests failed under concurrency. | Implemented idempotent index creation in FastAPI lifespan for unique constraints and analytical query patterns. |

### Reviewed Non-Defects

1. **Calendar date storage as strings (`YYYY-MM-DD`):** Examined whether `date` and `joined_on` should be stored as BSON dates. Decided this is correct per `DATA_MODEL.md` Section 1: calendar dates represent business days in IST without time zone distortion, unlike instant timestamps which are stored as UTC BSON dates.
2. **PyMongo timezone awareness:** `MongoClient(..., tz_aware=True)` was verified as the correct pattern to avoid naive datetime comparisons while ensuring UTC instants serialize properly to epoch milliseconds.
